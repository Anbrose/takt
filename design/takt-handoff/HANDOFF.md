# TAKT — 实现交接文档

这份文档汇总了设计阶段的全部产品决定，供实现时使用。`prototype/` 目录里是设计原型的源文件，作为参考。

## 怎么用 prototype/ 里的文件

- `logic.js`：规划界面全部状态逻辑的参考实现（层级、排序、勾选范围、距离、最短路线、拖拽、准备清单、进行中模式、新建任务）。**这是最值得读的文件。**
- `Phone.dc.html` / `PhoneDark.dc.html`：手机端主界面（浅色 / 深色）。
- `Main.dc.html` / `Dark.dc.html`：桌面端主界面。
- `Splash.dc.html` / `SplashDark.dc.html`：开屏动画。
- `Icon.dc.html` / `IconDark.dc.html`：App 图标（SVG）。

注意：`.dc.html` 是设计画布的专用格式，依赖画布自带的运行时（`support.js`、`<x-dc>`、`<sc-for>`、`<sc-if>`、`{{ }}` 占位），**不能直接在浏览器里单独打开运行**。把它们当作标记结构、内联样式数值和交互逻辑的参考，不要照搬这个格式。

## 技术栈（已定）

- **后端**：TypeScript。
- **前端页面**：TypeScript + React。
- **客户端**：目前只做 iOS，原生 Swift。选原生的原因是动画要流畅，动效是这个产品的重点（见「动效原则」）。

由此带来的约束：

- 任务树、排序、前置条件完成状态等数据由后端持久化，前端和 iOS 通过后端 API 读写。
- `prototype/logic.js` 里的规则（勾选范围、最短路线、准备清单排序、进行中模式的展开顺序）需要决定放在后端还是各端各自实现；建议纯展示和手势逻辑留在端上，数据规则放后端。
- "保存前不落库"的拖动排序意味着：端上维护草稿顺序，点保存才调一次更新顺序的接口。
- 后端和前端页面都是 TypeScript，任务、前置条件等类型定义和纯数据规则（如最短路线、准备清单排序）可以放在共享包里，两边复用。
- iOS 是 Swift，不能复用这个共享包：数据规则尽量由后端计算后返回，iOS 只在需要即时反馈的地方（如拖动中的预览距离）自己实现一份。
- 桌面端设计（`Main.dc.html` / `Dark.dc.html`）对应前端页面，手机端设计（`Phone*.dc.html`、`Splash*.dc.html`）对应 iOS 客户端。

## 产品是什么

TAKT 帮用户把一件事拆成有顺序的任务流，并在执行时告诉用户现在在哪、接下来做什么。示例场景是日本旅行：大阪 → 东京 → 北海道，每一站下面有若干景点子任务。标语：规划每一步。

## 数据模型

- 最顶层是 **Project**。"日本旅行"是一个 Project。
- Project 下是任务树。**每一级都是同一种任务**：大阪、东京是任务，大阪城也是任务。
- 每个任务有：名称、地点（文字 + 经纬度）、前置条件列表、可选的子任务列表。
- 前置条件是一个**列表**，每条有内容和紧急程度：尽早订（限量）/ 行前订 / 现场办。
- 同一级的任务是一个**有序列表，列表顺序就是执行顺序**。
- 原型只做了两层（Project → 站 → 景点），真实产品应支持任意深度。

## 规划模式

任意一级都是同一套界面：

1. **任务列表**：每项显示序号、名称、地点、前置条件标签；有子任务的显示"N 项 ›"可进入下一级。
2. **勾选只决定范围，不决定顺序**：不勾选时地图和准备清单按这一级全部任务计算；勾选后只算勾选项，顺序仍按列表。
3. **拖动排序**：
   - 每项右侧是三横把手，按住拖动，其他项平滑让位。
   - 开始拖动时，"取消 / 保存"从**屏幕底部**向上滑出并固定在底部。
   - **保存前不落库**；取消则任务滑回原位。
   - 拖动过程中，列表左侧让出一小列，用"序号 + 两字缩写"实时显示这一级的完整顺序，正在拖的项高亮；松手后收起。
   - 把手支持键盘上下方向键。
4. **地图（地理顺序）**：
   - 手机端：任务页和地图是同一个视图。进入地图时任务卡片**原地压缩**（收起地点、前置条件、子任务入口，只留勾选框、序号、名称、把手，并显示与上一项的距离），列表整体下移，地图在上方渐入。退出时反向。
   - 桌面端：地图常驻在列表右侧。
   - 地图按当前排列连线，显示总距离和状态：多绕 X km / 不绕路 / 预览中（拖动未保存时）。
   - "重排"按钮：固定第一项为起点，按最短路线重排。未保存的拖动期间隐藏。
   - 两组切换：优化目标（距离 | 耗时）、出行方式（步行 | 公交 | 自驾）。
5. **准备清单**：汇总范围内任务的前置条件，按紧急程度排序，可勾选完成。
6. **新建任务**：列表上方"+ 新建"入口，在**当前层级**末尾创建。表单从底部滑出，字段：名称、地点；前置条件默认折叠，点"+ 前置条件"逐行添加，可逐行删除。

## 进行中模式

顶部"规划 | 进行中"切换。进行中模式按规划好的顺序（深度优先展开到叶子任务）逐项推进：

- **现在**：当前任务、地点、它的前置条件（可勾选），"完成"按钮。
- **接下来**：下一项、与当前位置的距离、出发前要办的前置条件。跨段时（如大阪最后一项 → 东京第一项）提示，并把下一段自身的前置条件一并列出。
- **之后**：再往后三项预览。
- 顶部进度条和"2 / 16"。可"上一项"回退。
- 前置条件的完成状态与规划模式的准备清单是同一份。

## 视觉

- 主色：`#E6397C`（浅色模式）。深色模式底色：`#1A1A1D`。
- `#E6397C` 配白字或深色字对比度不足 4.5:1，所以：
  - 原色用于图形元素：路线、选中边框、标志、进度条。
  - 带文字的填充和粉色文字：浅色模式用 `#C2185B`（白字）；深色模式填充用 `#F272A3`（配 `#1A1A1D` 字），文字用 `#FF8AB5`。
- 完整色板见任一 `.dc.html` 里的 `.t-light` / `.t-dark` CSS 变量。
- 字体：Inter + Noto Sans SC。
- 触控目标不小于 44px。
- 文案风格：**图标 + 短字符串**，不写说明性长句（"地图""新建""重排""6 项""约 18 km"）。
- **不要"问 AI"之类的输入组件。**

## 动效原则

**用平移、拖动、线性过渡代替突然切换。** 原型里已经做的：

- 标签页、规划 / 进行中：整体水平平移，分段控件的高亮块滑动。
- 进入子任务 / 返回：内容从右 / 左滑入，返回按钮展开收起。
- 排序变化（拖动、重排、取消）：用 FLIP 让任务滑到新位置。
- 底部保存栏、新建表单：从底部滑出。
- 颜色、勾选、深浅色切换：渐变。
- 系统开启"减少动态效果"时全部关闭。

## 开屏与图标

- **开屏**：TAKT 四个字母按"节点流程"画出——起点节点出现，连线匀速画出，每到转折或分叉弹出一个节点，字母之间用细线相连，终点是实心粉色节点；之后标语和按钮淡入。约 2.6 秒。时间轴和坐标见 `Splash.dc.html`。
- **图标**：字母 T，横线上三个空心节点，竖线末端一个实心节点。主色版（粉底白线）和深色版。上架需导出 1024×1024。

## 原型的限制（实现时要补上的）

1. **地图是示意图**：点位按真实经纬度比例排布，距离是直线（haversine）估算。需要接真实地图（讨论过 Google Maps Platform）换成真实底图和实际里程 / 耗时。
2. **距离 / 耗时、出行方式切换目前不影响结果**，都按直线距离算。
3. **新建任务没有坐标**（原型里没有地点搜索），在地图上标为"未定位"。地点字段应接地点搜索。
4. **没有持久化**，状态只在内存里。
5. **没有 Project 列表页**（多个 Project 并列的那一级）。
6. **桌面端没有进行中模式**。
7. **新建的前置条件统一归为"行前订"**，没有紧急程度选择。
8. **最初设想里的 AI 辅助生成 flow 没有设计**，对话里只明确了不要"问 AI"输入框这种形式。
9. 示例数据的坐标是近似值，前置条件是按常识填的示例，不是核实过的购票规则。
10. "TAKT"这个名字没有查过商标和应用商店重名。

## 开工前需要先定的事

- 后端用哪个 TypeScript 运行时和框架（如 Node.js + NestJS / Fastify / Express）。
- iOS 用 SwiftUI 还是 UIKit（或混用）。拖动排序时的让位、底部栏滑出、任务 ↔ 地图的共享元素过渡是最吃动画能力的三处，选型时以它们为准。
- 是否需要账号体系和多设备同步，还是先做单用户。
- 数据库选型。
- 地图服务商（iOS 上 MapKit 与 Google Maps 的取舍；前端页面用哪家），以及"最短"默认按距离还是耗时。
- 路线计算放在后端统一调用，还是各端直接调地图 SDK。
- AI 辅助在产品里以什么形式出现。

## 建议的实现顺序

1. 后端：数据模型（Project、任务树、同级有序列表、前置条件）和基础 API（读取一级任务、新建、更新顺序、勾选前置条件完成）。
2. iOS：规划模式的任务列表——层级导航、勾选、新建。
3. iOS：拖动排序 + 底部保存 / 取消 + 左侧缩略栏。
4. 接入真实地图：点位、连线、距离、重排。
5. iOS：任务 ↔ 地图的共享元素过渡。
6. 准备清单。
7. 进行中模式。
8. 开屏动画、图标、深色模式。
9. 前端页面（React + TypeScript）：按桌面端设计实现，复用同一套 API。

iOS 和前端页面谁先做可以调整；上面的顺序假设先出 iOS。
